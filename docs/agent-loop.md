# 액션 루프 (실험) — JSON 액션 프로토콜 에이전트 루프

`python -m workshop.agenteval --mode loop` / 코드 화면의 방식 "액션 루프(실험)". 자율 에이전트 계획 Phase 1([autonomous-agent-plan.md](autonomous-agent-plan.md)).
**결론부터: 이 PC의 로컬 7B에서는 직접 모드보다 훨씬 나빴고 토큰도 4~6배 들었다. 약한 로컬 모델에는 쓰지 말고 [직접 모드](direct-mode.md)를 쓴다.** 더 강한 모델에서의 효과는 측정하지 못했다(그런 모델을 지금 쓸 수 없음).

## 구성 (구현됨, 의존성 0)
| 부분 | 파일 | 하는 일 |
|---|---|---|
| 정책 엔진 | `workshop/policy.py` | 도구 호출마다 허용/거부/승인필요를 한 곳에서 판단: 경로(복사본 안만, `.git`·비밀 이름·절대 경로·`..` 거부), 쓰기(파일 수 8개·크기 제한, 새 파일은 덮어쓰기 금지, **기존 테스트 파일은 읽기 전용**), 명령(never 목록 거부·허용 목록 실행·나머지는 승인 필요로 기록만) |
| 도구 계층 | `workshop/tools.py` | `list`·`read`(줄 범위)·`search`(글자/정규식)·`patch`(SEARCH/REPLACE, 정확히 한 번)·`create`·`run`(셸 없음, 허용 명령만, 시간 제한). 결과는 일부러 짧다(읽기 5천 자, 검색 25건, 명령 출력 끝 1,500자) |
| 루프 | `workshop/agentloop.py` | 모델이 한 번에 JSON 하나(`{"action":"read",...}`)로 답하고 JetAI가 판단·실행·결과를 돌려줌. 상태: plan → inspect → act → verify → (reflect) → complete. 마무리 전에 **JetAI가 직접 테스트를 돌려** 모델이 보고한 결과와 무관하게 판정(실패하면 최대 2번 고치게 함) |
| 한도 | `agentloop.DEFAULT_LIMITS` | 최대 단계 14·도구 호출 30·시간 600초·추정 토큰 8만·같은 실패 3번 반복 시 중단·고치기 2회. 화면/API의 `limits`로 조정(범위 검사) |
| 감사 로그 | `coderuns/<id>/audit.jsonl` | 도구 호출마다 한 줄(시도 번호·단계·상태·동작·인자 요약·결정·성공 여부·시간·결과 요약, 비밀 가림) |
| 연결 | `codework._run_direct` | 직접 모드와 **같은 실행 틀**(복사본·best-of-N·테스트 판정·보고서·승인 목록)을 재사용. 허용 명령 = 안전 고정 목록 + 프로젝트가 감지한/지정한 명령 + 사용자가 허용한 명령 |

## 토큰 절약 장치
- 파일은 줄 범위로 읽고 결과를 잘라서 돌려준다. 오래된 교환은 한 줄 요약으로 바꾸고 **최근 3번만 전문을 유지**(`Transcript`).
- 작업에 이름이 나온 작은 파일은 첫 메시지에 미리 넣어 한 번의 왕복을 줄인다. 관련 테스트는 읽기 전용 문맥으로 준다.
- 패치 실패 시 현재 파일 앞부분을 바로 돌려줘 다시 읽는 단계를 없앤다.
- 단계·도구 호출·추정 토큰(글자 2개당 1토큰)·시간 한도와 같은 실패 반복 감지로 헛도는 것을 막는다. 작업별 추정 토큰은 보고서와 하네스 표에 나온다.

## 실측 (2026-10-22, 로컬 `qwen2.5-coder:7b`, 어려운 작업 7개, 1회 시도)
| 방식 | 성공(작업×회) | 작업당 평균 추정 토큰 | 작업당 평균 시간 |
|---|---|---|---|
| **직접 모드** | 7/21 (33%) | 약 2,500 | 4~6초 |
| 액션 루프 v1 (처음) | 2/21 (10%) | 8,000~16,000 | 6~12초 |
| 액션 루프 v2(텍스트 블록 패치·실패 시 파일 앞부분·테스트 파일 읽기 전용·작업에 이름 나온 파일 미리 제공) | 0/7 (1회만 측정 후 중단) | 약 8,900 | 7초 |
| 액션 루프 v3(지시 모순 수정, 오류 답을 되돌려 보내지 않음) | 1/7, 0/7 (2회) | 약 8,900~10,700 | 8~9초 |

실패 모습(직접 확인): ① `{"action":"patch","path":"x"}` 한 줄만 쓰고 SEARCH/REPLACE 블록을 붙이지 않음 ② 잘못된 답을 `invalid`로 되돌려 보내면 모델이 그것을 따라 함(v3에서 고침) ③ JSON 안에 이스케이프한 여러 줄 코드는 정확히 일치하는 SEARCH를 못 만듦 ④ 테스트 파일을 고쳐 통과시키려 함(정책으로 막음).
해석: 여러 턴에 걸친 대화형 프로토콜은 7B에게 어렵고 토큰이 4~6배 든다. **한 가지 일만 시키는 짧은 질문(직접 모드)이 더 싸고 더 잘 된다.** 직접 모드를 이기려면 루프가 더 강한 모델에서 이득을 보여야 하는데 지금은 확인할 수단이 없다.

## 지금의 사용 규칙
- 화면의 "액션 루프(실험)"는 **약한 모델에 권장하지 않음**. 기본은 직접 모드. 라우팅 규칙(계획): 약 15B 이하 로컬 모델 → 직접 모드, 도구 호출을 잘하는 더 큰 모델이 생기면 루프를 측정한 뒤 허용.
- 막힌 명령은 목록에 기록되고, "항상 허용"을 누르면 프로젝트 규칙에 저장되어 **다음 작업부터** 적용된다(루프 작업은 세션이 없어 이어서 실행하지 않음).
- 한계: 브라우저·화면 조작 도구는 아직 없다(2~3단계). 에이전트 루프는 한 번에 한 가지 모델로만 돈다.
