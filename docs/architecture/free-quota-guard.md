# FreeQuotaGuard — 무료 한도 보호 (fail-closed)

목적: **새 API 비용 0원**. 공급자가 무료 잔액이나 결제 차단을 API로 보장하지 않는 서비스(첫 대상: Mercury 3)를, 확인된 조건이 모두 맞을 때만 호출한다. 구현: `workshop/quotaguard.py`, 호출 경로 연결 `workshop/chat.py`, 분류 연결 `workshop/usage.py`(`tier_for`).

## 열림 조건 (모두 참이어야 호출 가능)
1. 사용자가 켰다(기본 꺼짐).
2. 사용자가 **결제수단 미등록**을 직접 확인했다(시각 기록). JetAI는 이것을 공급자에게서 읽을 수 없다.
3. **무료 잔액이 알려져 있고 신선하다**: 공급자 대시보드에서 읽어 사용자가 입력한 값 + 입력 시각. 이후 JetAI가 쓴 토큰을 뺀다. 기본 24시간이 지나면 만료 → 차단(같은 키를 다른 곳에서 쓸 수 있어 내부 계산만으로는 실제 잔액을 보장하지 못하기 때문).
4. 사용자가 입력한 크레딧 기한이 지나지 않았다(모르면 비워 둠; 가격·크레딧 양은 코드에 넣지 않음).
5. 요청 하나가 **남은 잔액**(예약분 포함)과 **일일·월간 내부 한도**에 들어간다. 필요량 = (예상 입력 토큰 + min(요청 max_tokens, 요청당 최대 출력)) × (1 + 여유분%). 입력 예상은 일부러 높게(글자 2개당 1토큰).
6. 진행 중 요청이 `max_concurrent_requests`(기본 2) 미만이다. 요청 시작 시 **예약**하고 끝나면 정산하므로 여러 에이전트가 동시에 와도 초과하지 않는다(락 하나로 검사+예약을 원자적으로).

하나라도 어긋나면 `QuotaBlocked`가 **네트워크 호출 전에** 발생하고(`무료 한도 보호: …` 한국어 이유), 기존 모델 전환 로직이 다른 무료·로컬 모델로 넘어간다. 유료 모델로의 전환은 어디에도 없다(`allow_paid_fallback`은 존재하지 않고 항상 거부).

## 호출 후
- 실제 `usage`(prompt+completion)를 기록. 공급자가 사용량을 안 주면 **예약했던 추정치(더 큰 값)** 를 기록한다. 스트림을 도중에 끊어도 지금까지 쓴 만큼 정산.
- 오류가 나면 예약을 돌려준다. **재시도 루프 없음**(한 번 시도 후 실패면 다른 모델로).
- 응답 오류에 `HTTP 402`·`insufficient`·`credit`·`payment`·`billing`·`balance` 등이 있으면 **자동으로 꺼짐**(프로모션 종료·잔액 소진 신호로 간주). 401/403(키 거절)도 꺼짐. 다시 켜려면 사용자가 잔액을 다시 입력하고 켜야 한다.
- 결제 확인을 취소하면 즉시 꺼진다.

## 분류와 라우팅
- 가드가 걸린 서비스의 `tier_for`는 **열려 있을 때만 "free"**, 아니면 `"other"`(유료일 수 있음) → 자동 선택이 무료 풀에서 뺀다.
- 코드 작업(OpenCode)은 가드를 거치지 못하므로 가드 서비스를 모델 목록에서 제외하고 직접 지정도 거절.

## 상태 파일
`~/.agent-workshop/quota-guard.json`: 켜짐 여부, 확인 시각, 입력 잔액과 시각, 사용량 합계, 일·월 카운터, 내부 한도, 마지막 오류. **키는 들어가지 않는다.** 프로세스를 다시 시작해도 유지되지만, 설치되지 않은 가드(테스트·초기)는 항상 닫힘.

## 설정(화면에서 변경, 범위 검사)
`safety_margin_percent`(0~90, 기본 10), `max_request_output_tokens`(기본 4096), `daily_soft_limit_tokens`(1,000,000), `monthly_soft_limit_tokens`(10,000,000), `max_concurrent_requests`(2), `timeout_seconds`(60, 호출 시간 상한으로 적용), `balance_max_age_hours`(24). 값은 **사용자 초기 설정 예시일 뿐 공급자의 실제 한도가 아니다.**

## 한계 (솔직하게)
- 잔액은 사용자가 입력한 값이다. 공급자의 공식 잔액 API가 생기면 입력 대신 그 값을 쓰도록 `set_balance`의 호출처만 바꾸면 된다.
- 결제수단 미등록은 사용자의 확인이다. 등록해 버리면 보호가 무의미하다(화면에 경고).
- 다른 프로그램이 같은 키로 토큰을 쓰면 JetAI의 계산이 틀린다 → 만료 시간과 여유분이 완충.
- 코드 작업(OpenCode)은 보호 밖이라 쓰지 않는다.
