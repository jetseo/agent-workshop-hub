# 코드 작업 (코딩 에이전트 연동)

채팅이 아니라 **내 PC의 프로젝트 파일을 읽고 고치는** 작업입니다. JetAI가 코딩 에이전트(OpenCode)를 대신 실행하고, 결과를 diff로 보여 준 뒤 **내가 승인할 때만** 내 폴더에 적용합니다. 사이드바의 **코드** 화면에서 씁니다.

## 화면 (Claude Code·Codex 방식)
"코드" 화면은 한 화면의 에이전트 세션입니다.
- **왼쪽**: 작업 목록(상태 배지), 위에 "＋ 새 작업".
- **가운데 타임라인**: 내 요청(프로젝트 요약은 접힘) → 에이전트의 진행(읽기·수정·명령을 한 줄 카드로, 💬 설명은 말풍선, 실행 중엔 점 세 개) → 막힌 명령 승인 카드(그 자리에서 이번만/항상/거절) → 바뀐 파일별 접이식 diff → 빌드·테스트 카드 → 리뷰 카드 → 보고서. 아래쪽에 상황에 맞는 동작 버튼(적용·검사·리뷰·되돌리기·버리기·취소)이 따라다닙니다.
- **아래 입력창**: 프로젝트 폴더·모델·작업 지침 선택과 할 일 입력. **Ctrl+Enter**로 시작. **`/`** 를 치면 명령 목록(`/apply /undo /check /review /cancel /discard /new`, 한글 별칭 `/적용 /되돌리기 /검사 /리뷰 /취소 /버리기 /새작업`)이 나오고, 선택한 작업에 적용됩니다(확인 창은 그대로).
- 실행 중에는 1.5초마다 갱신하고, 위로 스크롤해 읽는 중이면 맨 아래로 끌어내리지 않습니다. 좁은 화면(폰)에서는 작업 목록이 위로 올라갑니다.
- 한계: 한 작업은 한 번의 지시로 끝납니다(같은 대화를 이어 말을 거는 방식은 아님). 후속 지시는 새 작업이 됩니다.

## 흐름
1. **프로젝트 폴더**(git 저장소)와 **할 일**을 적고 모델을 고른 뒤 **시작**.
2. JetAI가 마지막 커밋(HEAD)의 일회용 복사본(`git worktree`, 브랜치 `workshop/code-<id>`)을 만든다. 내 폴더는 건드리지 않는다.
3. OpenCode가 복사본 안에서 파일을 읽고 고치고 테스트를 돌린다. 화면에 진행(읽기·수정·명령·차단된 시도)이 보인다.
4. 끝나면 **바뀐 파일과 diff**(추가 초록, 삭제 빨강)를 본다.
5. **변경을 내 폴더에 적용**(확인 창 후 `git apply`, **커밋 안 함**) 또는 **버리기**(복사본·브랜치 삭제).

## 프로젝트 읽기
시작할 때 JetAI가 폴더 구조·문서·빌드/테스트 명령 후보를 미리 읽어 요청 뒤에 붙입니다(상세 화면에서 확인 가능). 읽기 전용이며 비밀 파일은 제외합니다.

## 직접 모드
화면의 방식에서 **직접 모드**를 고르면 OpenCode 대신 JetAI가 단계(위치 찾기 → 수정안 글 → 적용 → 테스트 → 한 번 고치기)를 진행하고 모델은 글로만 답합니다. 도구 호출을 못 하는 작은 로컬 모델도 작은 수정은 할 수 있습니다. 자세한 흐름·안전·실측은 [direct-mode.md](direct-mode.md).

## 작업 지침
시작 화면의 **작업 지침 붙이기**(**기본 꺼짐**, 설정 `code_guidance`. 쉬운 작업에서 시간만 약 2배 걸리고 정확도 이득이 없어 끔 — [agent-eval.md](agent-eval.md))가 켜져 있으면 요청 끝에 짧은 작업 방식 안내를 붙입니다: 먼저 읽기 → 테스트로 확인 → 범위 지키기 → 실제로 돌려 보고하기. 프로젝트에서 감지한 테스트 명령이 문구에 들어가고, 약한 모델(등급 1 이하)에는 3줄짜리 짧은 판을 씁니다. 출처와 만든 방식은 [skills-research.md](skills-research.md). 보고서에 쓴 지침 크기가 남습니다.
- **효과는 아직 측정하지 않았습니다.** `python -m workshop.agenteval --model 서비스/모델 --guidance both`로 같은 모델·작업을 지침 없음/있음으로 비교할 수 있습니다. 첫 측정에서 이득이 없어 기본값을 껐습니다.

## 코드 리뷰 (두 번째 의견)
상세 화면의 **코드 리뷰(다른 모델)** 를 누르면 수정한 모델과 **다른** 무료·로컬 모델이 원래 요청 + 빌드·테스트 결과 + diff를 읽고 판정(문제 없어 보임/주의/문제 있음/판단 불가), 문제 목록, 빠진 것을 보고합니다.
- 보고만 합니다. 자동 수정·적용 차단·재시도는 하지 않습니다(참고용). 유료·OpenCode 자체 모델은 쓰지 않고, 클라우드 서비스면 diff가 그곳으로 전송되므로 확인 창을 거칩니다.
- 답을 JSON으로 읽지 못하면 "판단 불가"로 표시합니다(통과로 보지 않음). 비밀처럼 보이는 문자열은 가립니다. 결과는 보고서에도 남습니다.
- 한계: 리뷰어의 품질은 모델에 달렸고 측정한 적이 없습니다. "지적 반영해 다시"는 재시도 기능(P1-6)에서 만듭니다.

## 빌드·테스트 검사
작업이 끝난 뒤 상세 화면의 **빌드·테스트 실행**을 누르면(확인 창 후) JetAI가 복사본에서 프로젝트 파일로 감지한 **빌드·테스트 명령만** 직접 실행하고 결과(통과/실패/시간 초과/도구 없음/테스트 없음)를 화면과 보고서에 적습니다.
- 사용자가 명령을 직접 넣을 수 없고(감지된 것만), 셸을 거치지 않으며, 최소 환경·명령당 5분 제한입니다. 린트는 실행하지 않습니다.
- 테스트 러너가 "실행된 테스트 없음"으로 끝나면 통과로 보지 않습니다.
- 자동으로 실행하지 않는 이유: 에이전트가 쓴 코드도 실행되기 때문입니다. 실패해도 적용을 막지는 않고 판단은 사용자가 합니다.

## 막힌 명령 승인
에이전트의 셸은 허용 목록 밖이면 막힙니다. 막힌 명령은 상세 화면에 목록으로 뜨고, **이번만 허용 / 이 프로젝트에서 항상 허용 / 거절**을 고를 수 있습니다. 허용하면 같은 복사본·같은 OpenCode 세션(`-s`)에서 이어서 실행합니다(OpenCode `run`은 도중에 묻지 못해 "끝난 뒤 승인 → 이어서 실행" 방식).
- 허용할 수 없는 명령(루트·홈 삭제, `git push`, `sudo`, 파이프 실행, 인코딩 명령, 디스크 포맷, 와일드카드 포함 등)은 버튼이 나오지 않습니다.
- 삭제·네트워크·패키지 설치·권한 변경 명령은 **이번만** 허용할 수 있고 "항상 허용"은 없습니다.
- 항상 허용은 `~/.agent-workshop/command-rules.json`에 프로젝트별로 저장되고(저장소 안이 아님), 다음 작업부터 처음부터 허용됩니다. 보고서에 결정 이력이 남습니다.
- 한계: 허용된 명령 안에서 일어나는 일(예: `npm test`가 내부에서 네트워크 사용)은 막지 못합니다. 실제 OpenCode에서 막힌 명령 이벤트를 관찰한 적은 없고(모의 에이전트로 확인), 판단은 "실패한 bash 호출 중 허용 목록에 없는 것"입니다.

## 에이전트 평가
모델이 코드 작업 에이전트로 쓸 만한지는 `python -m workshop.agenteval --model 서비스/모델`로 잰다(작은 작업 5개 자동 채점, 무료·로컬 모델만). 아직 실제 측정 결과는 없다.

## 적용 되돌리기
적용한 작업은 "적용 되돌리기"로 내 폴더에서 다시 뺄 수 있습니다(저장해 둔 패치를 거꾸로 적용, 확인 필요, 커밋 기록은 건드리지 않음). 적용 뒤에 같은 부분을 또 고쳤다면 `git apply -R --check`가 실패해 아무것도 바꾸지 않고 거절합니다. 상태는 "되돌림"으로 남습니다.

## 작업 보고서
작업이 멈출 때마다(끝남·실패·취소·적용·되돌림·버림) `~/.agent-workshop/coderuns/<id>/`에 `report.md`(목표·최종 판정·모델·프로젝트 요약·한 일·바뀐 파일)와 `metrics.json`(소요 시간·도구 호출 수·파일/줄 수·토큰(실행기가 알려 줄 때만)·적용/되돌림 여부)을 다시 씁니다. 상세 화면에서 읽을 수 있고, 비밀처럼 보이는 문자열은 가립니다. 빌드·테스트·리뷰 결과는 아직 자동 수집하지 않아 "기록 없음"으로 적습니다.

## 안전 규칙
| 규칙 | 구현 |
|---|---|
| 내가 눌러야 시작·적용 | 자동 실행·자동 적용 없음. 적용은 `confirm: true`가 있을 때만 |
| 복사본에서만 작업 | worktree. 적용 전 `git apply --check`가 통과해야 하고, 내가 같은 줄을 이미 고쳤다면 건드리지 않고 이유를 알림 |
| 권한 제한 | 수정만 허용, 셸 명령은 **허용 목록**(git status/diff/log/show, 테스트 실행, 버전 확인)만, 인터넷 가져오기·복사본 밖 폴더 접근 금지(`external_directory: deny`) |
| 내 설정·계정 격리 | OpenCode를 JetAI 전용 빈 설정/데이터 폴더(`~/.agent-workshop/opencode/`)로 실행: 내 OpenCode 플러그인·스킬·**유료 계정 키(OpenCode Zen, OpenAI)**가 전달되지 않음 |
| 환경 변수 최소화 | 셸의 토큰(`GITHUB_TOKEN`, `OPENAI_API_KEY` 등)을 넘기지 않음. 서비스 키는 변수 하나(`JETAI_PROVIDER_KEY`)로만 전달하고 설정 파일에는 쓰지 않음 |
| 비용 | 무료·로컬 모델만 기본. 요금이 나올 수 있는 모델은 비용 확인 체크 필요. OpenCode 자체 모델은 이름이 `-free`로 끝나는 것만 |
| 폭주 방지 | 한 번에 작업 하나, 20분 제한, 취소는 프로세스 트리 전체 종료, 앱을 끄면 같이 종료 |
| 명령 주입 방지 | 요청 글은 셸을 거치지 않고 인자 하나로 전달(실행 파일을 직접 시작) |
| 잡음 제거 | `__pycache__`, `*.pyc`, `.pytest_cache`, `node_modules`, `.venv` 등은 변경에 포함하지 않음 |
| 한글·BOM 보존 | 패치를 바이트 그대로 저장·적용(콘솔 코드페이지로 바꾸지 않음) |

## 모델 고르기 (시험으로 확인한 사실)
- **자동**: 무료·로컬 모델 중 코드 작업에 충분한 성능(등급 2 이상)만 고른다. **작은 로컬 모델(약 15B 이하)은 자동 선택하지 않는다.**
- 이 PC에서 시험한 결과:
  - `qwen2.5-coder:7b`(Ollama): 도구 호출을 구조화된 형태가 아니라 **글자로 내보내** 파일을 읽지도 못함 → 에이전트 작업 불가.
  - `gemma4:12b`(Ollama, 로컬): 도구 호출 형식은 맞지만 엉뚱한 계획·언어 혼용으로 빠져 **작업 실패**.
  - `opencode/deepseek-v4.1-flash-free`(OpenCode 무료 서비스): 35~45초 만에 버그를 고치고 테스트 명령을 실행, **성공**(2회). 코드가 그 서비스로 전송되므로 화면에 경고가 뜬다.
- 결론: 파일을 고치는 에이전트 작업은 **큰 모델이나 클라우드 무료 모델**에서 믿을 만하다. 작은 로컬 모델로는 질문·설명용 채팅이 낫다.

## 사용 전 확인
- OpenCode 설치: `npm i -g opencode-ai`(이 PC에는 1.19.3). Windows에서는 npm 스크립트(`opencode.cmd`)가 아니라 그 옆의 **실제 `opencode.exe`**를 직접 실행한다.
- 폴더는 `.git`이 있고 커밋이 하나 이상 있어야 한다. 저장하지 않은 변경은 복사본에 없다(화면에 경고).
- 커스텀 서비스(내 무료 키 등)로 실행할 때 OpenCode가 `@ai-sdk/openai-compatible` 패키지를 한 번 내려받는다(OpenCode 자체 동작, 네트워크 필요).

## 구조
`workshop/codework.py`(`CodeRuns`: 시작·실행·취소·diff 수집·적용·버리기), `workshop/adapters.py`(`windows_opencode_exe`), API `GET /code`, `POST /code/start`, `GET /code/runs/<id>`, `POST /code/runs/<id>/cancel|apply|discard`, 화면은 `static/app.js`의 코드 화면. 기록은 `~/.agent-workshop/coderuns/<id>/`(`run.json`, `events.jsonl`, `patch.diff`).
