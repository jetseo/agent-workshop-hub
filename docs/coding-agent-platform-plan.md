## 4. 이번 시험에서 얻은 핵심 사실
1. **모델이 병목**: 연결·격리·diff 흐름은 완성됐지만 작은 로컬 모델은 에이전트로 못 쓴다 → **평가 하네스로 측정**해야 한다.
2. **격리는 필수**: 내 전역 OpenCode 설정(플러그인·스킬)이 끼면 모델이 엉뚱한 일을 상상했다. 빈 설정으로 실행하자 깨끗해졌다.
3. **Windows 함정**: 콘솔 코드페이지(cp949)로 패치를 읽으면 한글 소스가 깨짐 → 바이트로 보관(수정됨). npm 스크립트(`.cmd`)는 따옴표 문제 → 실제 `.exe` 직접 실행.
4. 취소 경합, 상태 파일 동시 접근, "준비됨"과 서비스 등록의 순서 같은 **스레드 경합**이 Windows·느린 러너에서 실제로 났다 → 잠금·재시도·순서 정리(수정됨).

## 5. 설계
### 5.1 모델 관리 (다운로드·해시·버전·캐시)
- 모델 **레지스트리**(`engine/state.json` 확장): 파일명·크기·SHA-256·**HF 리비전(커밋 SHA)**·출처·형식·설치일·마지막 사용·사용 횟수.
- 카탈로그를 코드 밖 데이터로(`catalog/models.json`, 검증된 항목만): 코더 7B/14B, 범용 7B, 추론형, 작은 보조 모델. 새 모델은 **자동 설치가 아니라 "추천 후보"로 표시**(크기·라이선스·해시 확인 후 사용자가 설치).
- `verify`: 설치된 파일 재해시. 디스크 한도 설정, "오래 안 쓴 모델 정리" **제안**(자동 삭제 금지).
- 수용 기준: 리비전 고정 설치, 재검증 통과/실패 테스트, 정리 제안이 삭제를 하지 않음.

### 5.2 추론 엔진 — 형식별 연결과 메모리 기반 선택 (RTX 3060 12GB·RAM 64GB)
- **형식별 백엔드 추상화**(G6): `EngineBackend`(형식 → 실행 방법): `gguf` → llama.cpp(현재), 이후 후보는 다른 형식(예: safetensors·EXL2·ONNX)용 런타임을 같은 인터페이스(시작·종료·OpenAI 호환 주소·상태)로 추가. **당장은 GGUF만 구현**하고 인터페이스와 레지스트리의 `format` 필드만 만든다(중복 개발 방지).
- **메모리 예산 기반 선택**(G7): 정적 필요량 대신 **지금** 비어 있는 VRAM·RAM(`nvidia-smi` 사용 중 메모리, 가용 RAM)을 읽어 ① 올릴 수 있는 모델 후보 ② 양자화(Q4→Q5→Q8 중 들어가는 가장 큰 것) ③ 컨텍스트 길이 ④ GPU 레이어 수를 계산해 추천. 부족하면 CPU 혼합 실행(느림 표시) 또는 더 작은 모델 제안.
- **측정 전 추정**(실측으로 확정할 것): Q4_K_M 기준 7B(약 4.7GB)·Coder 14B(약 9GB)는 12GB에 올라가고, 20B급(약 11.6GB)은 컨텍스트를 거의 못 둔다. 에이전트는 컨텍스트가 빨리 커져 **8~16K가 필요**하므로 KV 캐시 여유까지 본다.
- 프로파일(컨텍스트·GPU 레이어·flash-attn·KV 양자화)을 모델별로 저장, 큰 모델은 요청 시 시작·유휴 시 종료(한 번에 하나), 설치 후 **도구 호출 시험**(`tools` 요청에 구조화된 `tool_calls`가 오는지)을 자동 수행해 "에이전트 가능" 표시, Vulkan vs CUDA 처리량 비교(실측).
- 수용 기준: 7B·14B의 시작 시간·토큰/초·최대 컨텍스트를 이 PC에서 측정해 문서화, 다른 프로그램이 VRAM을 쓰고 있을 때 추천이 달라짐(모의 테스트), 도구 호출 시험 결과가 화면에 표시.

### 5.3 외부 코딩 에이전트 연결과 구독 서비스 권한 검증
- `Executor` 인터페이스(시작·진행 이벤트·취소·결과)로 `codework.py`를 일반화: 지금 `opencode_command`/이벤트 요약이 OpenCode에 묶여 있음.
- **OpenCode**(완료) → **Codex CLI**·**Claude Code**(이 PC에 설치됨) → 자체 최소 에이전트(후순위).
- **구독형 실행기는 연결 전에 "자동화 사용 권한"을 검증**(G5, P0-7): ① 각 도구의 **공식 비대화형 모드**가 있는지(예: Codex의 비대화형 실행, Claude Code의 헤드리스 출력 모드) ② 구독(ChatGPT·Claude 계정) 로그인으로 자동화 호출이 **약관·이용 정책상 허용되는지**, 사용 한도·속도 제한 ③ API 키 방식은 유료이므로 금지. 결과를 `docs/subscription-tools.md`에 **출처 링크와 확인 날짜**와 함께 기록하고, **확인되기 전까지 코드 작업의 실행기 목록에서 제외**한다. 확인되더라도 기본 꺼짐·실행마다 확인·사용량 경고.
- 수용 기준: 실행기를 바꿔도 같은 화면·같은 격리 규칙·같은 diff 검토. 구독형 실행기는 검증 문서가 없으면 시작 불가(테스트로 보장).

### 5.4 오케스트레이터: 목표 입력 → 분해 → 할당 → 수정 → 검증 → 리뷰 → 보고
사용자가 **개발 목표 한 줄**을 입력하면(G1) 다음 단계를 작은 모듈로 연결한다. 각 단계는 독립 테스트가 가능해야 한다.
1. **분류**: 기존 `arbiter`로 종류·난이도(쉬운 수정은 작은 모델, 어려운 작업은 큰/클라우드 무료 모델).
2. **프로젝트 읽기**(5.8): 저장소 맵·문서 요약·빌드/테스트 명령 감지.
3. **계획**: 기존 `planner`로 목표를 하위 작업 1~4개로 분해(큰 목표만), 사용자가 계획을 보고 수정·승인.
4. **수정**: 하위 작업마다 독립 복사본에서 실행기가 작업(현재 구현). 모델은 `router`가 작업별로 할당.
5. **빌드·테스트(JetAI가 직접)**(G4): 감지된 빌드/테스트 명령을 **복사본에서 허용된 명령으로** 실행(시간 제한), 통과/실패/미실행 기록.
6. **코드 리뷰**(G3): 수정한 모델과 **다른** 무료 모델이 diff·테스트 결과·원래 요청을 읽고 "요청 충족 여부·위험·누락"을 짧게 보고(자동 수정은 하지 않고, 사용자가 "리뷰 지적 반영해 다시"를 누르면 새 복사본에서 재시도).
7. **판정·보고**: 테스트 통과 + 변경 범위(파일 수·삭제량·비밀 패턴) + 리뷰 결과로 "검토 권장/주의"를 표시하고, 보고서(.md)를 만든다(5.10).
8. **재시도 정책**: 실패 시 **새 복사본에서** 다른 모델로 1회, 상위(클라우드 무료/큰 로컬)로 올리는 것은 **사용자 확인**. 같은 모델 반복 금지, 최대 3회, 매번 기록.
- 병렬(G11): 의존성이 없는 하위 작업을 서로 다른 복사본에서 **동시에** 실행. 처음에는 순차로 완성하고, 하드웨어(VRAM) 한도와 한 번에 모델 하나 제약을 지키는 범위에서 단계적으로 늘린다(P2-3).
- 수용 기준: 의도적으로 틀린 수정을 하는 가짜 에이전트·가짜 리뷰어로 "검증 실패 → 재시도 → 에스컬레이션 확인", "리뷰 지적 → 사용자 선택" 흐름을 테스트.

### 5.5 격리·승인·권한·비밀·Git 이력
- 유지: worktree, deny-by-default, 환경 최소화, 키 격리, 적용 전 확인.
- **위험 명령 승인**(G9, P0-3): 막힌 명령을 화면(그리고 텔레그램)에 그 자리에서 띄워 **"이번만 허용 / 이 프로젝트에서 항상 허용 / 거절"**. OpenCode가 `run` 모드에서 질문을 못 하므로 ① 막힌 시도를 이벤트로 수집해 일시 중지 후 재개할 수 있는지 ② OpenCode 서버 모드/세션 이어가기로 가능한지 ❓ 먼저 확인. 승인은 이력으로 남기고, **삭제·네트워크·패키지 설치·권한 변경 명령은 "항상 허용"을 제공하지 않는다**.
- **적용 되돌리기**: 적용 시 역패치 보관, 파일이 그대로일 때 `git apply -R`.
- **Git 변경 이력**(G8, P1-5): 적용 방식 두 가지 — 기본(현재) "내 폴더에 변경만 적용(커밋 안 함)", 선택 "**작업 브랜치에 커밋**"(승인 후 `jetai/<slug>` 브랜치 생성·커밋, 메시지에 작업 ID·요청·모델 표기, 푸시·병합은 하지 않음). 브랜치 보존 옵션과 "이 작업의 커밋/패치 보기" 이력 화면.
- **비밀정보**: diff **비밀 패턴 검사**(키·토큰·`.env`·개인키)로 경고·적용 차단 옵션, 에이전트 읽기 금지 파일 목록(`.env`, `*.pem` …).
- 한계(문서에 명시): OS 수준 네트워크 차단은 하지 못한다(허용 목록 밖 명령은 막지만, 허용된 `npm test` 내부 네트워크 사용은 막지 못함).
- 수용 기준: 되돌리기 후 파일이 원래 바이트와 같음, 비밀 패턴이 든 diff는 경고, 위험 명령 승인 UI에서 "항상 허용"이 금지 목록에는 나오지 않음, 커밋 옵션이 푸시하지 않음.

### 5.6 측정: 토큰·시간·성공률
- 코드 작업마다 `metrics.json`: 시작·종료·소요, 모델, **입출력 토큰**(OpenCode JSON 이벤트에 토큰이 있는지 먼저 확인 ❓, 없으면 추정 표시), 도구 호출·차단 수, 빌드·테스트 결과, 리뷰 결과, 재시도 횟수, 최종 판정, 사용자 결정(적용/버림/커밋).
- 기존 `UsageLedger`(출처 `code`)와 `RunStats`에 연결 → 라우터가 에이전트 성공률로 모델을 고르게.
- 사용량 화면에 "코드 작업" 섹션: 작업 수·성공률·평균 시간·무료/로컬 비중.
- 수용 기준: 실제 실행 한 건의 지표가 화면·파일·보고서에 일치.

### 5.7 에이전트 평가 하네스 (핵심)

## 7. 완료 기준 — E2E 수용 시나리오 (요청문 ② 완료 기준)
"사용자가 하나의 개발 작업을 요청하면 JetAI가 프로젝트를 읽고, 안전한 브랜치에서 코드를 수정하고, 테스트한 후 결과와 변경 파일을 보고할 수 있어야 한다. 모든 변경은 Markdown에 기록한다."

| 단계 | 시나리오(예: 샘플 저장소에 "add 함수 버그를 고치고 테스트 통과") | 합격 조건 |
|---|---|---|
| ① 요청 | 개발 목표 한 줄 입력, 모델은 자동 | 시작 전 비용·전송 안내, 자동 선택 이유 표시 |
| ② 읽기 | 저장소 맵·문서·테스트 명령 감지 | 감지 결과가 보고서에 기록 |
| ③ 격리 | 일회용 브랜치/worktree에서 작업, 내 폴더 무변경 | 작업 중 내 폴더 `git status` 깨끗 |
| ④ 수정 | 에이전트가 파일을 읽고 고침, 위험 명령은 승인 요청 | 차단·승인이 이력에 남음 |
| ⑤ 검증 | JetAI가 테스트(와 빌드) 실행·판정 | 통과/실패가 정확히 기록 |
| ⑥ 리뷰 | 다른 모델의 리뷰 보고 | 요청 충족 여부·위험 요약 |
| ⑦ 보고 | 변경 파일·diff·테스트·리뷰·모델·시간·토큰을 화면과 `report.md`로 | 보고서만으로 무엇이 왜 바뀌었는지 이해 가능 |
| ⑧ 결정 | 적용(커밋 안 함) / 작업 브랜치 커밋 / 버리기 / 되돌리기 | 각 결정 후 상태가 보고서에 반영, 푸시·병합은 하지 않음 |
| ⑨ 복구 | 일부러 실패시킨 경우(검증 실패) | 새 복사본 재시도 또는 버리기로 내 폴더가 안전 |
이 시나리오를 **자동 테스트(가짜 에이전트)와 이 PC 실측(실제 에이전트, 무료 모델)** 두 가지로 통과하는 것이 이 계획의 1차 완료다. 이후 모델 라우팅·병렬 작업을 단계적으로 확장한다.

## 8. 위험과 사용자가 정할 것
1. **로컬 모델이 끝내 에이전트로 부족할 위험** — P0-2·3 결과에 따라 "코드 작업=클라우드 무료 모델" 정책으로 갈 수 있다(무료 키 연결 필요).
2. **Codex·Claude Code 허용 여부**: P0-7의 약관 확인 결과가 나온 뒤 결정. 허용돼도 기본 꺼짐·실행마다 확인.
3. **첫 실사용 저장소**: 어떤 프로젝트로 시험할지(복사본이라 안전하지만 코드가 클라우드 모델로 전송될 수 있음).
4. **다운로드 허락**: P0-2의 7B Coder(약 4.7GB), 이후 14B Coder(약 9GB).
5. **JetStudio 경계**: 영상·이미지 요구가 생기면 이 저장소가 아닌 JetStudio에서 다룬다.
6. **"작업 브랜치에 커밋"을 허용할지**(P1-5): 기본 정책 "커밋 안 함"을 바꾸는 선택이므로 켜기 전에 사용자 확인.
