# JetAI 코딩 에이전트 플랫폼 고도화 계획 (2026-10-22)

요청 문서("JetAI 코딩 에이전트 플랫폼 고도화")의 작업 순서 1~9를 **현재 저장소의 실제 상태**에 대어 정리한 계획입니다. 상태 표기: ✅ 구현·검증됨 · 🟡 일부 · ⬜ 아직 · ❓ 시험해 봐야 앎. "검증"은 어디서 확인했는지(모의 테스트 / GitHub 러너 / **이 PC 실측**)를 구분합니다. 기존 기능과 문서는 지우지 않고, 새 일은 작은 PR 단위로 나눕니다.

## 1. 절대 조건 점검
| 조건 | 상태 | 근거 / 갭 |
|---|---|---|

## 4. 이번 시험에서 얻은 핵심 사실
1. **모델이 병목**: 연결·격리·diff 흐름은 완성됐지만, 작은 로컬 모델은 에이전트로 못 쓴다. 로컬 모델이 쓸 만한지는 **평가 하네스로 측정**해야 한다.
2. **격리는 필수**: 내 전역 OpenCode 설정(플러그인·스킬)이 끼어들면 모델이 엉뚱한 일을 상상했다. 빈 설정으로 실행하자 도구가 깨끗해졌다.
3. **Windows 함정**: 콘솔 코드페이지(cp949)로 패치를 해석하면 한글 소스가 깨진다 → 바이트로 보관(수정 완료). npm 스크립트(`.cmd`)는 따옴표 문제 → 실제 `.exe` 직접 실행.
4. 취소 경합, 상태 파일 동시 접근 같은 **스레드 경합**이 Windows에서 실제로 났다 → 잠금+재시도.

## 5. 설계
### 5.1 모델 관리 (다운로드·해시·버전·캐시)
- 모델 **레지스트리**(`engine/state.json` 확장): 파일명·크기·SHA-256·**HF 리비전(커밋 SHA)**·출처·설치일·마지막 사용·사용 횟수.
- 카탈로그를 코드 밖 데이터로(`catalog/models.json`, 검증된 항목만): 코더 7B/14B, 범용 7B, 추론형, 작은 보조 모델. 새 모델은 **자동 추가가 아니라 "추천 후보"로 표시**(크기·라이선스·해시 확인 후 사용자가 설치).
- `verify`: 설치된 파일을 다시 해시해 손상 확인. 디스크 한도 설정과 "오래 안 쓴 모델 정리" 제안(자동 삭제 금지).
- 수용 기준: 리비전 고정 설치, 재검증 통과/실패 시나리오 테스트, 정리 제안이 삭제를 하지 않음.

### 5.2 경량 추론 엔진 (RTX 3060 12GB 기준)
- **측정 전 추정**(실측으로 확정할 것): Q4_K_M 기준 7B(약 4.7GB)·Coder 14B(약 9GB)는 12GB에 올라가고, 20B급(약 11.6GB)은 컨텍스트를 거의 못 둔다. 에이전트는 파일 내용과 도구 결과로 컨텍스트가 빨리 커져 **8~16K 컨텍스트가 필요**하므로 KV 캐시 여유까지 봐야 한다.
- 설계: ① 엔진 시작 옵션을 모델별 **프로파일**로(컨텍스트 크기, GPU 레이어, flash-attn, KV 캐시 양자화) ② 큰 모델은 요청 시 시작·유휴 시 종료(한 번에 하나) ③ **도구 호출 확인 시험**(`tools` 요청에 구조화된 `tool_calls`가 오는지)을 설치 후 자동 수행해 "에이전트 가능" 표시를 단다 ④ Vulkan vs CUDA 처리량 비교(실측).
- 수용 기준: 7B·14B 각각 시작 시간·토큰/초·최대 컨텍스트를 이 PC에서 측정해 문서화, 도구 호출 시험 통과/실패가 화면에 표시.

### 5.3 에이전트 연결 구조
- `Executor` 인터페이스(시작·진행 이벤트·취소·결과)로 `codework.py`를 일반화: 지금 `opencode_command`/이벤트 요약이 OpenCode에 묶여 있음 → 실행기별 어댑터.
- 실행기 후보: **OpenCode**(완료) → **Codex CLI**·**Claude Code**(이 PC에 설치됨, **구독 토큰을 쓰므로** 기본 꺼짐·실행 전 명시적 확인·사용량 경고) → 자체 최소 에이전트(후순위: OpenCode가 충분하면 불필요).
- 수용 기준: 실행기를 바꿔도 같은 화면·같은 격리 규칙·같은 diff 검토. 구독형 실행기는 확인 없이는 시작 불가.

### 5.4 작업 분해·난이도·라우팅·검증·재시도 (코드 작업 파이프라인)
`요청 → (분류) → 계획 → 수정 → 검증 → 판정` 을 작은 단계로:
1. **분류**: 기존 `arbiter`로 종류·난이도. 쉬운 수정은 작은 모델, 어려운 작업은 큰/클라우드 무료 모델.
2. **계획(선택)**: 큰 작업만 `planner`로 1~4개 하위 작업. 각 하위 작업은 독립 복사본.
3. **수정**: 실행기가 복사본에서 작업(현재 구현).
4. **검증(새로 만듦)**: 프로젝트의 테스트 명령 자동 감지(`pytest`/`unittest`/`npm test`/`dotnet test`…, 사용자가 수정 가능)를 **JetAI가 복사본에서 직접 실행**(허용된 명령·시간 제한)해 통과/실패/미실행을 기록.
5. **판정**: 테스트 통과 + 변경 범위 점검(파일 수·삭제량·비밀 패턴) → "검토 대기(권장)" / "주의" 표시.
6. **재시도 정책**: 실패 시 **새 복사본에서**(부작용이 내 폴더에 없으므로 안전) 다른 모델로 1회, 그다음 상위(클라우드 무료/큰 로컬)로 에스컬레이션은 **사용자 확인**. 같은 모델 반복 금지, 최대 3회, 매번 기록.
- 수용 기준: 의도적으로 틀린 수정을 하는 가짜 에이전트로 "검증 실패 → 재시도 → 에스컬레이션 확인" 흐름을 테스트.

### 5.5 격리·승인·권한·비밀
- 유지: worktree, deny-by-default, 환경 최소화, 키 격리, 적용 전 확인.
- 추가: ① **적용 되돌리기**: 적용 시 역패치 보관, 파일이 그대로일 때 `git apply -R` ② **명령 1회 승인**: 막힌 명령을 화면에 띄워 "이번만 허용" (OpenCode가 `run` 모드에서 질문을 못 하므로 서버 모드/재시작 방식 검토 필요 ❓) ③ 프로젝트별 허용 목록 편집 ④ diff **비밀 패턴 검사**(키·토큰·`.env`·개인키) 경고와 적용 차단 옵션 ⑤ 에이전트가 읽으면 안 되는 파일 목록(`.env`, `*.pem` …) 
- 한계(문서에 명시): OS 수준 네트워크 차단은 하지 못한다(허용 목록 밖 명령은 막지만, 허용된 `npm test` 같은 명령이 내부에서 네트워크를 쓸 수 있음).
- 수용 기준: 되돌리기 후 파일이 원래 바이트와 같음, 비밀 패턴이 든 diff는 경고, 되돌리기 불가 상황(그사이 수정)은 안내.

### 5.6 측정: 토큰·시간·성공률
- 코드 작업마다 `metrics.json`: 시작·종료·소요, 모델, **입출력 토큰**(OpenCode JSON 이벤트에 토큰 정보가 있는지 먼저 확인 ❓, 없으면 추정 표시), 도구 호출 수·차단 수, 검증 결과, 재시도 횟수, 최종 판정, 사용자 결정(적용/버림).
- 기존 `UsageLedger`(출처 `code`)와 `RunStats`(모델별 성공·실패)에 연결 → 라우터가 에이전트 성공률로 모델을 고르게.
- 사용량 화면에 "코드 작업" 섹션: 작업 수·성공률·평균 시간·무료/로컬 비중.
- 수용 기준: 실제 실행 한 건의 지표가 화면과 파일에 일치.

### 5.7 에이전트 평가 하네스 (핵심)
- `scripts/agent_eval/`: 작은 **작업 세트 10개 내외**(버그 수정, 함수 추가, 테스트 작성, 리팩터, 한글 주석/BOM 파일, 여러 파일 변경, 일부러 모호한 요청, 위험한 요구("모든 파일 삭제")에 대한 거절/차단 …). 각 작업은 일회용 저장소 + 자동 채점(테스트 통과, 변경 범위, 금지 행동 없음).
- 모델·실행기 조합마다 실행해 **성공률·시간·토큰**을 표로 → `docs/agent-eval.md`에 기록하고 라우터 통계의 초기값으로 사용.
- 이것으로 "내장 엔진의 Qwen2.5 Coder 7B/14B가 에이전트로 쓸 만한가?"를 **측정으로** 답한다. 쓸 만한 모델이 없으면 "코드 작업은 클라우드 무료 모델, 로컬은 채팅·압축·계획"으로 정책을 확정.

## 7. 위험과 사용자가 정할 것
1. **로컬 모델이 끝내 에이전트로 부족할 위험** — P0-2·3 결과에 따라 "코드 작업=클라우드 무료 모델" 정책으로 갈 수 있다. (무료 키 연결이 필요)
2. **Codex·Claude Code 실행기 허용 여부**(P2-1): 둘 다 구독 토큰을 쓴다. 허용하더라도 기본 꺼짐·실행마다 확인.
3. **첫 실사용 저장소**: 어떤 프로젝트로 시험할지(읽기만 하는 복사본이라 안전하지만, 코드가 클라우드 모델로 전송될 수 있음).
4. **다운로드 허락**: P0-2의 7B Coder(약 4.7GB), 이후 14B Coder(약 9GB).
5. **JetStudio 경계**: 이 계획에는 영상·이미지 기능이 없다. 만들 모델·작업 중 영상 쪽 요구가 생기면 이 저장소가 아닌 JetStudio에서 다룬다.
