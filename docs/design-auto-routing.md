# 설계서(SDD): 자동 선택과 이어서 작업하기

앱 안의 **(?)** 도움말은 이 문서의 요약입니다. 상태 표기: ✅ 구현·테스트됨 · 🟡 구현했으나 실서비스 미검증 · ⬜ 아직 안 함.

## 1. 목적
사용자는 여러 AI 서비스를 연결해 두고 **그냥 질문**한다. JetAI가 질문의 종류와 양을 보고 알맞은 모델을 고르며, 모델이 달라도 같은 대화의 내용을 이어서 안다. 유료 호출은 하지 않는다.

## 2. 요구사항
| # | 요구 | 상태 |
|---|---|---|
| R1 | 질문 종류(코드 / 일상 / 심층 조사)와 양·난이도를 판단 | ✅ 아비터 |
| R2 | 종류에 맞는 **성능**의 모델을 선택(무료·로컬 안에서) | ✅ 라우터(이름 기반 성능 추정) 🟡 |
| R3 | 한도·오류 시 자동으로 다음 모델로 이어서 답변 | ✅ |
| R4 | 모델이 바뀌어도 같은 대화의 정보를 공유 | ✅ 같은 대화 안 |
| R5 | 긴 대화에서도 원래 목표를 잃지 않음 | 🟡 메모(요청 목록)만, 답변 요약 ⬜ |
| R6 | 다른 대화·작업 사이의 공유 기억 | ⬜ |
| R7 | 요금이 날 수 있는 모델은 쓰지 않음 | ✅ |
| R8 | 서비스의 모델이 수십 개여도 사용자가 고르지 않음 | ✅ 추천 모델 자동 저장 |
| R9 | 모델이 어떤 것이고 무엇에 적합한지 인터넷 정보로 분류 | ✅ 공개 목록(OpenRouter) 🟡 |
| R10 | 실행할 때마다 새 무료·로컬 모델을 확인해 자동 추가 | ✅ 🟡 실서비스 |

## 3. 구성
```
질문 ─▶ 아비터(arbiter.py) ─▶ 라우터(router.route_task) ─▶ 모델 호출(chat_api) ─▶ 답변 + "자동 선택 — …" 표시
          종류·난이도           성능 등급·특기·쿨다운          실패하면 다음 후보로 이어서
               ▲                      ▲                        │
        직전 대화의 종류          modelpick.capability       대화 기록(chat_store) + 앞선 대화 메모
                                  runstats(성공·실패)
```
### 3.1 아비터 — `workshop/arbiter.py`
입력: 질문 글, (선택) 앞선 대화의 종류. 출력: `{type, level, confidence, reasons}`.
- **종류**: 코드 모양(```, `def`, 스택 트레이스, 파일 확장자)·코드 단어 → `code`. 조사·비교·분석·보고서·출처·여러 항목(번호/불릿 3개 이상)·긴 글 → `research`. 그 밖 → `chat`.
- **난이도(1~3)**: 길이(400/2,500자), 항목 수, 어려운 주제 단어(아키텍처·동시성·보안·최적화…)로 올린다. 조사는 최소 2. 가벼운 질문(번역·"뭐야")은 1.
- **후속 질문**: 자기만의 신호가 없고 짧은 말("왜?", "그럼 더 빠르게?")만 앞선 대화의 종류를 이어받는다. 새 주제는 이어받지 않는다.
- 모델을 부르지 않으므로 비용 0. 규칙이라 틀릴 수 있다(예: 코드 단어가 없는 코드 질문).

### 3.2 모델 성능 추정 — `workshop/modelpick.py`
이름만으로 등급을 짐작한다(벤치마크 아님): `lite·mini·nano·small·instant·haiku`=1(가벼움), `pro·large·opus·sonnet·ultra`나 60B 이상=3(고성능), `flash`·중간 크기·알 수 없음=2. 특기: `coder`(코드), `r1·thinking·qwq`(추론).
서비스의 모델 목록은 정리해서 보여준다: `models/` 접두사 제거, 음성·이미지·임베딩·안전분류·실시간 모델 숨김, preview·latest 별칭은 추천에서 제외, **추천 최대 5개**(빠른 것 2 + 강한 것 2 + 코드 1, 시리즈가 겹치지 않게).

### 3.3 라우터 — `workshop/router.py: route_task`
후보: 연결·동의한 서비스의 **로컬 + 무료** 모델(유료는 후보가 아님). 점수(낮을수록 좋음): 필요한 등급보다 모자라면 3배 감점, 남으면 1배; 코드 질문에서 코드 모델 −1.5, 조사에서 추론 모델 −1, 일상 질문에서 코드 모델 +0.5. 동점이면 내 PC → 덜 쓴 모델 → 이름. 방금 실패한 모델은 60초, 연속 실패는 10분, 30일 실패율 50% 초과는 제외.
실패 시 이어서 답할 후보도 같은 점수 순서로 정한다.

### 3.4 이어서 작업하기 — `chat_api._history`
- 대화는 이 PC에 저장되고, 질문할 때마다 **최근 약 24,000자**를 그때 답하는 모델에 함께 보낸다 → 같은 대화 안에서는 모델이 바뀌어도 맥락이 같다(R4).
- 넘치면 오래된 부분을 빼고 맨 앞에 **메모**를 붙인다: 처음 요청(400자) + 그 뒤 빠진 요청들(최대 10개, 각 100자). 모델 호출 없이 만든다(R5의 일부).
- 서로 다른 대화는 공유하지 않는다(R6). 여러 모델이 한 작업을 나눌 때는 **보드**의 공유 마크다운 문서를 쓴다.

### 3.5 무료 판정 — `usage.tier_for`
로컬 / 이름이 `-free`·`:free` / 카탈로그의 "무료 티어"(`free: all`, 결제 수단 없는 키) / 이름 일부(`free_match`, 예: Zhipu의 `flash`) → 무료. 그 밖 → "그 밖(요금 가능)". 결제를 연결한 키는 한도 초과분에 요금이 나올 수 있어 화면에 경고한다.

### 3.6 모델 정보 수집 — `workshop/modelinfo.py`
모델을 추가하거나 라우팅할 때 **인터넷의 공개 정보**를 쓴다. OpenRouter의 공개 모델 목록(`openrouter.ai/api/v1/models`, 키 불필요, 약 450개)에는 문맥 길이·추론 지원·이미지 입력·가격·설명과, 많은 모델에는 Artificial Analysis의 **벤치마크 점수**(지능 지수·코딩 지수)가 들어 있다.
- 하루에 한 번만 받아 `~/.agent-workshop/modelinfo.json`에 줄여서 저장한다. 받기에 실패하면 이전 사본을 쓴다. 내 PC 정보는 보내지 않는다(익명 GET 한 번).
- 연결한 모델 이름과 목록의 이름을 정규화해서(`models/` 접두사, 벤더, `-instruct`·`-versatile`·`:free`·날짜 제거) 정확히 맞는 것만 연결한다.
- 벤치마크 순위(목록 전체의 하위 30% / 중간 / 상위 30%)를 이름으로 짐작한 등급과 **평균**내어 성능 등급으로 쓴다(`70b` 같은 이름이 오해를 부르기 때문). 코딩 지수 상위, 추론 지원, 문맥 길이 20만 이상, 이미지 입력은 태그로 보여 준다.
- 마법사의 추천 모델에 태그와 설명(마우스를 올리면 표시)이 나온다. 목록에 없는 모델은 이름으로 짐작한다.

### 3.7 새 모델 자동 확인·추가 — `workshop/modelwatch.py`
- JetAI를 실행할 때(10분에 한 번까지) 연결한 서비스의 모델 목록을 다시 받아 지난번(`models-seen.json`)과 비교한다. **처음 보는 서비스는 목록만 기억**하고 추가하지 않는다.
- 새 모델 중 **무료·로컬이고 채팅이 되는 것**만, 서비스마다 최대 2개(서로 다른 종류 우선)를 등록한다. 요금이 날 수 있는 모델, 음성·이미지·임베딩·미리보기, 이상한 이름은 건너뛴다. 동의하지 않은 서비스에는 접속하지 않는다.
- 추가한 내용은 화면 알림으로 한 번 알리고(`model-news.json`), 설정에서 끄거나 "지금 확인"을 누를 수 있다. 모델 파일을 내려받지는 않는다.
- 백그라운드 스레드에서 실행하므로 시작이 느려지지 않고, 실패해도 조용히 다음 실행에서 다시 시도한다.

## 4. 데이터·인터페이스
- `POST /api/v1/chats/<id>/send` (model=`auto`): SSE `meta`에 `{model, auto, task, level, why}`.
- `POST /api/v1/onboard/models`: `{models, recommended, total, hidden}`. `POST /api/v1/onboard/test`는 `extra_models`(쉼표, 최대 6개, 이름 검증)를 함께 저장.
- `GET /state`: `news`, `settings`. `POST /settings` `{auto_add_models}`, `POST /models/check`, `POST /news/ack`. `POST /onboard/models`에는 `info`(추천 모델별 태그·설명)가 추가된다.
- 저장: `providers.json`(`free_all`, `free_match`, `models`), `runstats.jsonl`(모델별 성공·실패·시간; 프롬프트 없음).

## 5. 안전 제약
자동 유료 호출 없음 · 동의하지 않은 클라우드 제외 · 키는 저장소 밖 · 127.0.0.1만 · 선택 이유를 화면에 표시 · 언제든 모델을 직접 고를 수 있음.

## 6. 검증
단위 테스트(`tests/test_arbiter_curation.py`, `test_chat_api.py`의 `ArbiterChatTests`, `OnboardingSaveTests`)와 앱 내 브라우저(가짜 Gemini 모양 서버: 16개 모델 → 8개 표시·5개 추천, 일상/조사/코드 질문이 서로 다른 모델로 감). **실제 Gemini·Groq 등 키로는 미검증**이고, 성능 추정이 실제 품질과 맞는지는 사용하며 확인해야 한다.

## 7. 한계와 다음 단계
- 공개 목록에 없는 모델(예: Ollama에서 받은 작은 모델, 새로 나온 모델)은 이름으로 짐작한다. 벤치마크는 목록 안의 상대 순위이고 모든 모델에 있지는 않다.
- 이름 기반 성능 추정·키워드 분류는 틀릴 수 있다 → 사용 기록(성공률·사용자의 "다시 생성")으로 보정하는 것이 다음 단계.
- 답변 요약(긴 대화 압축)과 대화 사이 공유 기억, 파일·작업 단위 메모는 아직 없다(R5·R6).
- 큐 워커·보드의 `auto` 단계는 아직 이전 방식(난이도만 보고 선택)이다 → 아비터로 통일 예정.
- **내장 로컬 엔진**(Ollama 없이 JetAI가 직접 모델을 받아 실행): 가능하지만 아직 아니다. llama.cpp 서버 실행 파일과 모델 파일(수 GB)을 받아야 하고, 모델 자동 다운로드는 사용자 동의가 필요하다. 지금은 Ollama(또는 호환 서버)를 쓴다.
