# 기능 목록 (기록용)

JetAI Hub의 목적은 **개발 토큰 절약**입니다(`CLAUDE.md`의 프로젝트 범위 참조). Jet Studio(쇼츠 제작)는 별개의 프로젝트입니다.
이 문서는 "무엇이 있는가"를 기록합니다. 삭제나 이동을 뜻하지 않습니다. 검증 상태는 `docs/verification.md`가 기준입니다.

## 토큰 절약 방향 (핵심, 계속 개발)
| 기능 | 위치 | 설명 |
|---|---|---|
| 채팅 창 + 온보딩 마법사 | `workshop/app_page.py`, `static/app.js`, `chat_api.py`, `setup_page.py` | ChatGPT/Claude 형태의 대화 화면에서 무료·로컬·저비용 서비스를 연결하고 대화 |
| 서비스 등록과 토큰 보관 | `providers.py` | 키는 저장소 밖(`secrets.json`, 600), 데이터 정책 태그, 클라우드 동의 기록 |
| 사용량 기록·자동 전환 | `usage.py`, `chat_api.py` | 등급(로컬/무료/유료)별 토큰 기록(추정 vs 서비스 보고), 429 시 로컬·무료 모델로만 자동 전환 |
| 긴 글 압축(digest) | `digest.py`, 압축 탭, `python -m workshop.digest` | 긴 로그·문서를 무료/로컬 모델로 조각별 요약 후 합쳐 유료 모델에 넘길 토큰 절약. 유료 모델은 비용 확인 필요, 요약 부정확 경고 상시 표시 |
| 서비스별 분당 요청 제한(rpm) | `ratelimit.py`, `onboard --rpm` | rpm을 넘기면 15초 이내는 기다리고, 더 길면 보내기 전에 막아 429와 쿼터 낭비를 피함(막힌 요청은 자동 전환 대상). 0이면 무제한 |
| 첫 실행 환경 점검 | `envcheck.py`, `/api/v1/env`, 마법사 1단계 | Ollama 실행 여부·모델 수, WSL 유무(Windows), 파이썬 버전을 읽기 전용으로 확인해 안내(설치·시작·다운로드 없음). Ollama가 있으면 해당 카드를 추천 표시 |
| 큐 작업 사용량 기록 | `worker.py`, `cli --model`, 대시보드 모델 칸 | 큐의 OpenCode 작업에 모델(`provider/name`)을 지정하면 로컬·무료로 분류해 추정치로 사용량에 기록(출처 "작업 큐"). 유료로 분류되는 모델은 큐에서 실행하지 않음(보드에서 비용 확인 후 사용). 모델을 안 정하면 등급을 알 수 없어 기록하지 않음 |
| 연결 실패 원인 안내 | `explain.py` | 401·403·404·429·리다이렉트·5xx, 연결 거부·시간 초과·주소 오류·SSL·응답 형식 오류를 쉬운 한국어 원인과 다음 행동으로 설명(원문은 괄호로 유지). 마법사 테스트, 모델 목록, 채팅 오류에 적용. 첫 화면에 "나중에 할게요" 버튼 |
| 멀티 모델 보드 | `board.py`, `orchestrator.py`, `plan_board.py` | 공유 MD 문서로 여러 모델이 직렬/병렬 협업, 요청 한 줄로 보드 생성 |
| 비용 안전장치 | `modelpolicy.py`, orchestrator 게이트 | 유료·구독 모델 기본 차단(`-free`, `:free`, 로컬만 허용), 클라우드는 명시적 동의 |
| 일회용 worktree 코드 단계 | `worktree.py` | 코드 수정은 임시 worktree에서만, diff만 보고하고 커밋·병합 안 함 |
| OpenCode 연동 | `adapters.py` | WSL 네이티브 OpenCode로 무료 모델 실행(Windows 쪽 바이너리는 거부) |
| 모델 라우터 | `router.py`, `docs/queue.md` | 난이도·역할별로 로컬→무료 순 모델 선택, 유료는 자동 선택 안 함(승인 필요 표시), 실패율 높은 모델 제외. 판단만 하고 호출하지 않음 |
| 결과 캐시 | `cache.py`, `--cache` | 같은 모델·같은 프롬프트의 텍스트 단계는 모델을 다시 부르지 않고 저장된 답을 사용(7일, 500개 상한), 절약 토큰 추정치 기록. 동의·클라우드 게이트는 캐시보다 먼저 적용 |
| 로그 전처리 | `logsum.py`, 압축 탭 체크박스, `python -m workshop.logsum` | 모델 호출 전 무료로 줄임: 색상 코드 제거, 시각·숫자만 다른 반복 줄 합치기(xN), 오류·경고 줄과 앞뒤 문맥·처음·끝 유지, 글자 예산 초과 시 오류 줄 우선. 압축(digest)에서 기본 켜짐 |
| 사용량 페이지 절감 표시 | `usage.py` | 무료·로컬이 처리한 토큰(유료였다면 소모했을 양, 추정)과 캐시 재사용으로 아낀 토큰 |
| 로컬 계획 | `planner.py`, `plan_cli.py` | 로컬 Ollama로 요청을 작업 1~4개로 분해(읽기 전용) |

## 인프라 (보존)
작업 큐(`queue.py`: 승인·하트비트 복구·의존성·취소·재시도·체크포인트·동시 실행 제한), 워커(`worker.py`), 대시보드(`dashboard.py`), 진단(`diagnostics.py`, `preflight.py`, `doctor.py`),
내장 터미널(`terminal.py`, `websocket.py`, xterm.js), Windows 런처와 설치 스크립트(`start.ps1`, `install.ps1`, `scripts/`), CI(`.github/workflows/validate.yml`).

## 제거된 기능: 이미지·ComfyUI
쇼츠 제작(Jet Studio) 쪽 기능이라 사용자 결정으로 이 저장소에서 **모두 제거**했습니다(작업 종류 `image`, ComfyUI 제출·상태·다운로드, 대시보드 갤러리, 설치 스크립트, 진단 항목). 코드와 설명은 `docs/handoff/jet-studio-comfyui-prompt.md`에 Jet Studio용 프롬프트로 옮겨 두었습니다. 기존 작업 DB에 남은 `image` 작업은 실행되지 않고 목록에만 보입니다.

## 한 서비스에 계정(키) 여러 개 등록 (구현됨, 실서비스 미검증)
무료 토큰을 주는 서비스를 많이 쓰게 될 것이라, 한 서비스에 **사용자가 직접 가진 계정·키를 여러 개** 등록해 번갈아 쓰는 기능입니다. 모델 선택 메뉴의 "계정(키) 여러 개 관리"에서 추가·삭제합니다.
- 구현 범위: 서비스당 최대 10개, 계정별 분당 한도(rpm), 첫 키는 "기본" 계정, 추가 키는 `secrets.json`에 따로 저장하고 화면에는 끝 4자리만 표시. 등록할 때 "본인이 발급받았고 약관이 허용하는 계정" 확인이 필요함(서버도 확인). 429가 나면 같은 모델로 다음 계정을 먼저 시도하고, 모든 계정이 실패하면 기존 모델 자동 전환으로 넘어감. 아래 설계 메모는 처음 계획 그대로임.
- 서비스 하나 아래에 계정 목록(별칭, 키, 개별 rpm·일일 한도, 사용량 표시). 키는 지금처럼 저장소 밖 `secrets.json`에만 보관.
- 호출은 한도가 남은 계정부터 순서대로 사용하고, 429나 한도 초과 시 다음 계정으로 넘김(기존 자동 전환과 같은 규칙: 로컬·무료·동의한 서비스만).
- 화면: 마법사와 설정에 "계정 추가" 버튼, 모델 선택·사용량 화면에 계정별 현황.
- **만들지 않는 것:** 계정 자동 생성, 가입 우회, 약관이 금지하는 한도 회피. 대부분의 무료 서비스는 한 사람이 여러 계정을 만들어 무료 한도를 늘리는 것을 약관으로 금지하며, 적발되면 계정이 정지될 수 있습니다. 약관상 허용되는 경우(개인 계정과 팀·회사 계정 등 서로 다른 사용 주체)에만 쓰도록 화면에 안내 문구를 둡니다.

## 최종 목표: 설치해서 쓰는 프로그램 (로드맵, 아직 구현 안 함)
사용자가 설치 파일을 받아 실행하면 바로 온보딩부터 시작되는 일반 프로그램 형태가 최종 목표입니다.
1. **Windows 단독 실행:** 채팅·온보딩·압축·사용량은 표준 라이브러리만 쓰므로 WSL 없이 Windows 파이썬으로 실행되게 합니다. 터미널(PTY)·OpenCode·worktree만 WSL이 필요한 선택 기능으로 분리하고, 없으면 해당 탭만 안내 문구를 보입니다.
2. **설치 패키지:** 내장 파이썬을 포함한 설치 파일(예: Inno Setup)로 시작 메뉴·바탕화면 바로가기와 제거 기능까지 제공. 관리자 권한, 모델 다운로드, 자동 업데이트는 하지 않음(명시적 선택만).
3. **첫 실행 온보딩:** 환경 점검(WSL·Ollama·OpenCode는 선택) → 서비스 연결(키 입력·테스트) → 첫 대화. 건너뛰고 나중에 설정에서 해도 됨.
4. **검증:** GitHub 러너에서 설치 → 실행 → 종료 → 제거 스모크 테스트, 이후 사용자 PC에서 실기기 확인(둘을 구분해 기록).
