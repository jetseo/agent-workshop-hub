# 작업 목록 삭제 불가: 원인 분석(RCA) (2026-10-23)

범위: 코드 화면의 **작업(code run) 목록**. 채팅 목록은 별도이며 삭제가 이미 된다(`static/app.js` `deleteChat` → `DELETE /api/v1/chats/<id>` → `chat_store.delete`).
방법: 코드 읽기(`workshop/codework.py`, `chat_api.py`, `static/app.js`)와 이 PC에서 본 화면(사용자 스크린샷)으로 추적. **아직 버그를 고치기 위한 코드 수정은 하지 않았고, 아래는 읽어서 확인한 사실이다.**

## 결론: "삭제가 실패"하는 것이 아니라 **삭제 기능 자체가 없다**
| 확인 항목 | 실제 코드 | 결과 |
|---|---|---|
| 작업 삭제 API | `_code_api`(`chat_api.py`)의 `runs/<id>/` 동작: `cancel` `apply` `review` `check` `webcheck` `command` `undo` `discard` 뿐. **delete·archive·rename 없음** | 없음 |
| "버리기" 버튼의 실제 동작 | `CodeRuns.discard`(`codework.py` ~990): 작업용 **복사본(worktree)만 지우고** `status="discarded"`로 바꿈. `run.json` 폴더는 그대로 | 기록은 남음 → 목록에 "버림"으로 계속 보임 |
| 목록 | `CodeRuns.list`: `coderuns/*/run.json`을 수정 시각순으로 읽고 **`KEEP_RUNS = 30`개만 반환**. 삭제 개념이 없어 오래된 작업은 그냥 화면에서 사라지고 새 작업이 쌓이면 밀려남 | 사용자는 지울 수도, 보관할 수도 없고, 30개를 넘으면 조용히 안 보임(디스크에는 남음) |
| 식별자 | `RUN_ID = [0-9a-f]{12}`, 작업마다 고유. 제목은 프롬프트 첫 줄이라 같은 제목이 여러 개 있어도 **ID는 겹치지 않음** | 식별 문제는 아님 |
| 이름 변경 | 없음(제목 = 프롬프트) | 없음 |
| 낙관적 업데이트·경합 | 목록은 1.5초마다 서버에서 다시 읽음(`renderCode`). 클라이언트에 삭제 상태가 없어 되살아나는 현상 자체가 없음 | 해당 없음 |
| 백그라운드가 지운 작업을 되살림 | 삭제가 없으므로 해당 없음. 단, 앞으로 구현할 때 **실행 중 작업의 `_save`가 삭제 표시를 덮어쓰는 경합**은 막아야 함(`_lock` 안에서 읽고-쓰기) | 설계 주의점 |
| 프로젝트 파일 영향 | 작업 기록 폴더는 `~/.agent-workshop/coderuns/<id>/`, 작업용 복사본은 별도 `worktrees` 폴더. **사용자의 프로젝트 폴더와 분리**되어 있음 | 기록 삭제가 소스를 지우지 않도록 구조적으로 안전 |

## 사용자가 본 증상과의 연결
스크린샷에서 "버림" 배지의 작업이 20개 가까이 쌓여 있고(평가 하네스가 만든 것 포함) 지울 방법이 없음. "버리기"를 눌러도 목록에서 사라지지 않는 것은 **의도된 동작이었지만 이름이 오해를 부름**(복사본 정리 ≠ 기록 삭제).

## 수정 방침 (엔진 영향: **없음**)
`run.json`에 **표시 필드만 추가**하는 소프트 삭제(되돌릴 수 있음). 코드 실행 엔진·모델 호출·worktree 로직은 건드리지 않는다.
- `archived_at`(보관), `deleted_at`(휴지통), `title`(이름 변경, 없으면 프롬프트 첫 줄). 기존 `run.json`에는 필드가 없어도 정상(기본값 = 일반 목록) → **하위 호환**.
- 새 동작(`CodeRuns`): `rename` · `archive` · `unarchive` · `trash` · `restore` · `purge`(영구 삭제, 확인 필수) · 일괄 처리.
- 상태 규칙: `running`은 보관·삭제 거부("먼저 중지") / 대기·완료·실패·취소·버림은 가능 / 휴지통 항목은 `list()` 기본에서 제외.
- `trash` 시 아직 남은 작업용 복사본이 있으면 정리(이미 있는 `_remove_worktree`), **사용자 프로젝트(`repo`)는 건드리지 않음**.
- `purge`는 `coderuns/<id>/` 폴더만 삭제(경로가 `runs_dir` 아래인지 확인 후). 휴지통 자동 비우기는 하지 않음(사용자가 누를 때만).
- `list()`의 30개 제한을 **필터별로 적용**하거나 "더 보기"로 바꿔 조용히 사라지는 일을 없앰(기본 화면은 최근 30개, 검색하면 전체).

## 재현·검증 절차(구현 후)
1. 같은 제목의 작업 2개 생성 → 하나만 삭제 → 다른 하나와 프로젝트 파일 유지.
2. 삭제 → 목록 새로고침 → 앱 재실행(트레이 종료 후 다시 실행) → 기본 목록에 없음, 휴지통에 있음.
3. 휴지통 복원 → 원래 위치로.
4. 실행 중 작업 삭제 시도 → 거부 메시지.
5. 삭제 직후 서버 오류를 주입 → 오류 토스트와 목록 변화 없음.
6. 영구 삭제 → 해당 `coderuns/<id>` 폴더만 사라짐, 다른 작업·프로젝트 폴더 무사.
