# JetAI UI 기존 구조 조사 (2026-10-23)

기준: main(PR #56까지 + 진행 중 PR). 조사 방법은 코드 읽기와 내장 브라우저 측정이다. "엔진 영향"은 모델 실행·라우터·에이전트·워크트리 로직을 바꾸는지 여부.

## 기술 스택과 구조
- **프론트엔드**: 프레임워크 없음. 서버가 `app_page.py`로 HTML을 만들고 `static/app.js`(약 1600줄, `h()` 도우미로 DOM 생성)와 `static/app.css`를 서빙. 의존성 0이 원칙(결정 D1)이라 **새 UI 라이브러리를 넣지 않는다**.
- **화면**: 채팅 / 코드 작업 / 설정 / 작업(큐) / 보드 / 사용량(iframe) / 압축 / 터미널(WSL). 좌측 사이드바 + 가운데 화면 + (코드 화면만) 작업 목록·변경 패널.
- **백엔드**: `chat_api.py`가 `/api/v1/...` 라우팅, `codework.py`(`CodeRuns`)가 코드 작업, 파일 저장(JSON·JSONL)이며 `~/.agent-workshop/` 아래(`coderuns/<id>/`, 채팅, 설정). DB 마이그레이션 없음.
- **디자인 토큰**: `app.css` 상단 CSS 변수(`--bg --accent --side-w --runs-w --chg-w` 등), 밝은/어두운 테마, Claude 스타일 레이어(2026-10-23).
- **상태 동기화**: 코드 화면은 실행 중일 때 1.5초마다 `GET /code/runs`·`/code/runs/<id>`를 다시 읽음(폴링). 서버가 단일 진실 원천.

## 제약 정리
- 실제로 **없는** 데이터(예: GPU 사용률 실시간, 비용)는 가짜 숫자로 채우지 않는다. 있는 값만 표시하고 없으면 "기록 없음".
- GitHub Actions는 이 저장소에서 이미 PR마다 돌고 있다(새로 켜거나 바꾸지 않는다). 로컬에서는 **관련 테스트만** 돌린다.
