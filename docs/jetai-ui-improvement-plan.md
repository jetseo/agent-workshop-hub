# JetAI UI/UX 고도화·작업 관리 안정화 플랜 (2026-10-23)

근거: 사용자가 준 "UI/UX 고도화 및 작업 관리 안정화 마스터 프롬프트", 실제 코드 조사(`docs/jetai-ui-existing-architecture.md`), 삭제 원인 분석(`docs/jetai-task-deletion-rca.md`). 이 문서는 **계획**이며 아래 구현은 아직 시작하지 않았다(진행 현황은 맨 아래 체크리스트).

## 1. 프롬프트 분석 — 요점과 현실 대조
| 프롬프트 요구 | 이 저장소의 실제 상황 | 계획에서의 처리 |
|---|---|---|
| 엔진·스택·저장소 절대 보존 | 맞는 방향. UI는 단일 `app.js`, 저장은 JSON 파일 | 전부 **표시 필드 추가·읽기 어댑터·UI**로만 해결. 엔진 영향 "없음"이 목표 |
| P0 삭제가 안 됨 | **삭제 기능이 아예 없음**(버리기는 복사본만 정리). 오류가 아니라 미구현 | 소프트 삭제(보관·휴지통·복원·영구 삭제) 신설 |
| 이름 변경·복제·보관·삭제 메뉴 | 전부 없음 | 행의 더보기(⋯) 메뉴. 복제는 "다시 실행(같은 설정으로 새 작업)"으로 구현 |
| 검색·필터·정렬·다중 선택 | 없음 | U2(작업 관리) |
| 좌측 폭 조절, 우측 패널 열기·닫기·저장 | **이미 구현**(U1, S2) | 중복 개발 안 함 |
| 변경 파일·Diff·테스트 결과 | **이미 있음**(변경 패널, 검사 카드) | 연결·정리만 |
| 모델·자원·토큰 표시 | 일부만(설정·보고서) | 작업 상세 요약 카드로 연결, 없는 값은 "기록 없음" |
| 새 UI 라이브러리 금지 | 프로젝트 원칙(D1)과 일치 | 순수 JS/CSS 유지 |
| 전체 테스트 반복 금지 | 사용자 지시와 일치 | 관련 테스트만 로컬 실행, 전체는 PR의 CI(이미 있음, 새로 켜지 않음) |
| "엔진 변경이 필요하면 보류" | — | 아래 "보류 후보"에 모음 |

**프롬프트와 충돌하거나 조정이 필요한 점**
1. "GitHub Actions를 임의로 활성화하지 않는다": 이 저장소는 이미 PR마다 CI가 돈다. **그대로 두고 수정하지 않는다.**
2. "삭제 후 앱 재실행해도 유지": 저장은 파일이므로 표시 필드를 `run.json`에 기록하면 충족. 단, 실행 중인 스레드가 같은 파일을 다시 저장하므로 읽기-수정-쓰기를 기존 `_lock` 안에서 해야 한다(경합 방지).
3. "화면 제목만으로 식별 금지": 이미 12자리 고유 ID 사용 중 — 유지.
4. "작업 삭제 ≠ 소스 삭제": 기록 폴더(`coderuns/<id>`)와 작업용 복사본·사용자 프로젝트가 분리돼 있어 구조적으로 안전. 영구 삭제도 `coderuns/<id>`만 지운다.

## 2. 단계 (각각 독립 PR, 작게)
### P0 — 삭제·보관·휴지통 (엔진 영향: 없음)
- 백엔드: `CodeRuns.rename/archive/unarchive/trash/restore/purge` + `list(view="active|archived|trash", q=…)`; API `POST /code/runs/<id>/{rename,archive,unarchive,trash,restore,purge}`, `POST /code/runs/bulk`.
- 규칙: 실행 중은 보관·삭제 거부, 휴지통은 목록 기본에서 제외, 영구 삭제는 `confirm:true` 필수, 일괄 처리는 건별 결과 반환.
- 프론트: 작업 행 ⋯ 메뉴(이름 변경·다시 실행·보관·삭제), 삭제 후 "휴지통으로 이동했습니다 · 되돌리기" 토스트, 목록 상단의 보기 전환(작업/보관/휴지통), 영구 삭제 확인창(범위·복구 불가 명시).
- 기존 "버리기"의 이름을 "복사본 정리"로 바꿔 혼동 제거.
- 완료 기준: RCA 문서 6단계 시나리오 통과(관련 테스트 + 앱 재실행 확인).

### P1-a — 작업 목록 UX
- 검색(제목·프로젝트·모델), 상태 필터 칩, 정렬(최근 실행·생성·이름), 프로젝트별 그룹(접기), 다중 선택·일괄 보관/삭제, 같은 제목 구분(프로젝트명·시각 보조 줄), 30개 제한을 "더 보기"로 대체.
- 긴 제목: 한 줄 말줄임 + 툴팁 + 상세 머리글에 전체 제목(이미 부분 구현).

### P1-b — 대화·실행 상태 표시 (기존 데이터만 사용)
- 타임라인을 **계획 → 실행 → 검증** 3단 접힘 구간으로 정리(`activity`·`events.jsonl`·검사 결과를 읽기만), 중지·재시도·승인 요청 가시성 강화, 완료 후 결과 요약 카드.
- 데이터가 없는 모드(에이전트 방식은 도구 단계 정보가 적음)는 있는 만큼만 표시하고 "이 방식은 기록하지 않음" 빈 상태.

### P1-c — 작업 상세 요약·모델·사용량
- 작업 상세 머리글: 모델·방식·시도·실행 시간·**실측 토큰(서비스가 센 값)과 추정치 구분 표기**·잘림 경고. 값이 없으면 "기록 없음".
- 모델 연결 실패 원인(이미 `explain` 모듈이 있음)을 칩/메뉴에 노출. 하드웨어 줄은 `engine.status()` 값이 있을 때만(CPU/GPU 실시간 새 측정은 만들지 않음).

### P2 — 통합 검증·문서
- 회귀 확인(채팅·코드 작업 시작·승인·적용/되돌리기·모델 연결), 앱 재실행 후 보존, 패널 상태 저장, 접근성(키보드 이동), 좁은 창.

## 3. 보류 후보 (엔진·구조 변경이 필요해 지금은 하지 않음)
- CPU/GPU 사용률의 **실시간 그래프**(새 측정 루프 필요).
- 작업 중간 단계의 **토큰 단위 스트리밍 표시**(에이전트 방식은 실행기가 알려 주지 않음).
- 변경 **승인·롤백 세분화**(파일/hunk 단위)는 현재 적용·되돌리기 엔진과 충돌 가능 → 별도 설계 후 승인.
- 비용 정확 추적(유료 서비스 가격표 필요; 무료·로컬 우선 정책이라 후순위).

## 4. 위험과 대응
| 위험 | 대응 |
|---|---|
| `run.json` 읽기-쓰기 경합으로 삭제 표시가 덮임 | `_lock` 안에서 처리 + 실행 중 작업은 삭제 거부 + 테스트로 고정 |
| 기존 데이터 호환 | 새 필드는 모두 선택 사항(없으면 기본), 기존 `run.json` 수정 없음 |
| 영구 삭제 경로 오류 | `coderuns/<id>`가 `runs_dir` 아래인지 `resolve()` 비교 후 삭제, ID 정규식 통과만 |
| `app.js` 비대화 | 새 UI 코드는 함수 단위로 묶고 필요하면 정적 파일 분리 검토(의존성 추가 없음) |
| 토큰 절약 요구 | 로컬 테스트는 관련 파일만, 전체는 CI |

## 5. 사용자에게 확인하고 싶은 것 (답이 없으면 기본값으로 진행)
1. 휴지통 보관 기간: **기본 = 자동 삭제 없음**(사용자가 "비우기"를 눌러야 지움). 30일 자동 삭제를 원하면 알려 주세요.
2. "다시 실행"은 **같은 프롬프트·설정으로 새 복사본에서 새 작업**(기존 작업 덮어쓰기 아님)으로 구현.
3. 평가 하네스가 만든 작업(`jetai-eval-*` 프로젝트)은 일괄 보관 대상으로 **프로젝트 필터에서 쉽게 고르게**만 하고 자동 삭제하지 않음.
