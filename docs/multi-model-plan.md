# 멀티 모델 협업 계획 (초안 v1)

상태: **계획 단계. 코드는 아직 없음.** 프로젝트 이름/브랜딩은 보류(내부명 Agent Workshop Hub).

## 목표
1. 여러 무료/로컬/클라우드 AI를 **온보딩 마법사**로 쉽게 등록한다.
2. 등록된 모델들이 **하나의 공유 Markdown 파일(보드)** 을 읽고 쓰며 한 작업을 **직렬 또는 병렬**로 함께 진행한다.
3. UI는 일반 채팅 앱 수준으로 단순하게(채팅 + 진행 상황 + 보드 보기).

## 기존 구조 위에 얹는 방식
기존 큐/승인/하트비트/명시적 opt-in을 그대로 쓰고 아래를 추가한다.

| 구성요소 | 역할 | 비고 |
|---|---|---|
| Provider 레지스트리 | 모델 공급자 목록·상태 | `config/providers.yaml`(카탈로그, 커밋) + 사용자 설정(커밋 안 함) |
| 온보딩 마법사 | 공급자 선택 → 키 입력 → 연결 테스트 | CLI 먼저, 이후 대시보드 |
| 비밀 저장소 | API 키 보관 | 저장소 밖(`~/.agent-workshop/secrets`, 권한 600) 또는 환경변수. 로그/보드에 절대 기록 금지 |
| 어댑터 | 공급자별 호출 | 1순위 **OpenAI 호환 `/chat/completions`** 하나로 대부분 커버, Ollama·OpenCode는 기존 어댑터 |
| 보드(공유 MD) | 모델 간 공유 작업 공간 | 아래 참조 |
| 오케스트레이터 | 단계(직렬/병렬) 실행 | 큐의 job 하나 = 보드의 step 하나 |

### 온보딩 마법사 흐름
1. 카탈로그에서 공급자 선택(로컬 Ollama, OpenAI 호환 무료 티어 서비스 등).
2. 키 입력(화면에 재표시 안 함) → 비밀 저장소에 저장.
3. **사용자 동의 후** 최소 요청 1회로 연결 테스트(토큰 1~5개 수준).
4. 모델 목록·한도(분당/일일 요청 수)·**데이터 정책 태그**(학습 사용 여부, 로컬/클라우드) 기록.
5. 요약 카드 표시: "이 모델은 클라우드, 입력이 외부로 전송됨" 등.

원칙: 무료라도 **자동 결제 경로·자동 모델 다운로드 없음**, 무료 티어 한도는 서비스가 수시로 바꾸므로 코드에 하드코딩하지 않고 카탈로그/사용자 설정에서 읽는다.

### 보드(공유 Markdown) 설계
한 작업 = 한 폴더 `~/.agent-workshop/boards/<task-id>/board.md` (+ `steps/` 아래 단계별 출력).
```
# 작업: <제목>
## 목표 / 제약          ← 사람이 작성, 모델은 읽기 전용
## 계획 (steps)         ← 오케스트레이터가 관리: id, 담당 모델, 의존성, 상태
## 공유 컨텍스트        ← 합의된 사실·결정 (추가 전용)
## 단계별 산출물        ← step마다 자기 섹션만 쓰기
## 검토 / 이슈
```
- **쓰기 충돌 방지:** 병렬 단계는 각자 `steps/<id>.md`에만 쓰고, 오케스트레이터가 완료 시 보드에 병합(단일 작성자).
- **추가 전용 + 이력:** 덮어쓰기 대신 버전/해시를 남겨 되돌릴 수 있게 한다.
- **컨텍스트 한도:** 보드가 커지면 모델마다 필요한 섹션만 잘라 전달(요약 단계 포함). 한도가 작은 무료 모델을 고려.

### 실행 모드
- **직렬:** A → B → C, 이전 산출물을 다음 입력으로.
- **병렬(팬아웃):** 같은 질문을 여러 모델에 → 비교/투표/종합 단계로 수렴.
- **혼합:** 의존성 그래프(DAG). 각 노드에 담당 모델, 타임아웃, 필요 승인 지정.
- 레이트리밋: 공급자별 동시 호출 수·분당 한도 큐잉, 429는 대기 후 **읽기 전용 호출만** 재시도 가능.

## 안전 규칙 (기존 원칙 유지)
- AI 실행은 항상 명시적 opt-in. 코드 수정은 임시 worktree에서만, 병합은 사람 승인.
- 부수효과가 있는 단계는 자동 재시도 금지. 텍스트 생성 단계(부수효과 없음)만 재시도 허용 옵션.
- 비밀 키 로그/보드/에러 메시지 마스킹, 대시보드는 loopback 유지.
- 민감 파일을 클라우드 모델에 보내기 전 경고(데이터 정책 태그 기반).

## 단계별 구현 로드맵
1. **M1 공급자 레지스트리 + 비밀 저장소 + OpenAI 호환 어댑터** (모의 서버로 테스트, 네트워크 불필요)
2. **M2 온보딩 CLI** (`python -m workshop.onboard`): 목록/추가/테스트/제거, 동의 프롬프트
3. **M3 보드 파일 포맷 + 파서/작성기** (충돌·이력 테스트)
4. **M4 오케스트레이터**: 직렬 → 병렬 → DAG, 큐 job과 연결, 하트비트/복구 재사용
5. **M5 대시보드 UI**: 채팅형 입력, 단계 진행 표시, 보드 뷰어, 온보딩 화면
6. **M6 실제 공급자 검증**: 사용자 PC·키로 실행한 결과만 "검증됨"으로 기록

M1~M4는 클라우드/모의 서버로 개발·CI 가능. M6와 Windows 동작은 사용자 환경이 필요.

## 결정이 필요한 항목
1. **첫 지원 공급자:** 로컬 Ollama + OpenAI 호환 서비스 중 어떤 무료 서비스를 우선할지(키를 가진 곳 기준).
2. **키 저장 방식:** 파일(권한 600) vs Windows 자격 증명 관리자(WSL에서 접근이 번거로움).
3. **보드 병합 주체:** 항상 오케스트레이터(안전, 권장) vs 모델이 직접 편집(유연, 충돌 위험).
4. **데이터 민감도:** 클라우드 모델에 코드/문서를 보내도 되는 범위의 기본값.
5. **UI 형태:** 지금의 서버 렌더 HTML 확장(권장, 의존성 없음) vs 별도 프런트엔드 프레임워크.
