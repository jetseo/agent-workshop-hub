# 프로젝트 등록과 프로젝트별 설정

JetAI가 일할 수 있는 프로젝트를 등록해 두고, 프로젝트마다 명령·브랜치·권한 정책을 따로 둔다. 구현: `workshop/projects.py`, API `/api/v1/projects`, 화면은 **코드** 탭의 프로젝트 선택(⚙ 설정).

## 원칙
- **모든 코드 작업은 등록된 프로젝트의 일회용 복사본(git worktree)에서만** 한다. 프로젝트 폴더 자체는 "적용"을 누를 때만 바뀐다.
- 폴더를 직접 입력해 시작하면 **처음 한 번 자동으로 등록**된다(작업 기록에 프로젝트 이름이 남는다).
- 등록 해제는 목록에서 빼는 것뿐이다. **폴더·작업 기록은 지우지 않는다.**
- JetAI는 다른 프로젝트(JetStudio·JetFlight …)의 소스를 자기 저장소에 넣지 않는다. 경로만 가리킨다. 각 프로젝트의 파일은 사용자 승인 없이 고치지 않는다.

## 저장되는 것 (`~/.agent-workshop/projects.json`, 비밀 없음)
| 항목 | 설명 |
|---|---|
| 이름·id·경로 | id는 이름에서 만든 영문 슬러그(겹치면 -2, -3). 경로는 git 저장소 폴더만(드라이브·홈 전체·JetAI 자료 폴더·시스템 폴더는 거부) |
| 원격·기본 브랜치·언어·지침 파일 | 자동 감지(`refresh`로 다시). 원격 주소의 `사용자:토큰@`는 저장하지 않음 |
| 감지된 명령 | `projectmap`이 찾은 빌드·테스트·린트 후보(읽기 전용) |
| 내 명령 | 빌드·테스트·실행·린트를 직접 지정하면 **감지된 같은 종류를 대체**(검사·직접 모드 테스트가 사용). `git push`·삭제·`sudo`·파이프 실행·와일드카드가 든 명령은 저장 불가 |
| 작업 브랜치 이름 | 영문·숫자·`.`·`_`·`-`·`/` |
| 개발 서버 주소 | **이 PC(localhost·127.0.0.1)의 http(s)만**(브라우저 검증용, 2단계) |
| 허용 앱 | 화면 조작(3단계)을 허용할 앱 이름 최대 10개 |
| 정책 | `commit`: `never`(기본)·`ask`(승인 후 작업 브랜치 커밋), `computer_use`: `observe`(기본)·`approval`. **자동 모드는 아직 없음** |
| 마지막 작업 | 목록 정렬(최근 순)에 사용 |

## 아직 안 하는 것
- 커밋·푸시·PR은 만들지 않았다(`commit` 정책은 저장만, P1-5에서 구현, 승인 후에만).
- 허용 앱·화면 조작 모드·개발 서버 주소는 저장만 하고 아직 쓰는 기능이 없다(2~3단계).
- 프로젝트별 지침 파일 우선순위·권한 정책의 세부 적용은 1단계(정책 엔진).
