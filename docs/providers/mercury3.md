# Mercury 3 (Inception Labs) — 공급자 조사와 연결 방법

확인일: 2026-10-22. 근거가 **공식 문서**인지 **실제 API 응답**인지 **보조 자료**인지 표시한다. 확인하지 못한 것은 `UNVERIFIED`.

## UNVERIFIED (확인하지 못했거나 자료끼리 어긋남)
- **무료 잔액 조회 API**: 공식 문서에 **없음**. 응답의 `usage`는 토큰 수뿐이고 남은 크레딧을 알려 주지 않는다(대시보드에서만 확인 가능한 것으로 보임).
- **무료 크레딧 유효기간**: 문서에 없음.
- **소진 후 자동 과금 여부**: 문서에 없음. 결제 정보를 등록하지 않은 계정은 청구 대상이 없다는 점이 사실상의 보호 수단이다(아래).
- **지출 한도(spend cap)·결제 차단 API**: 문서에 없음.
- **무료 요금제 속도 제한**: 문서가 어긋난다 — 검색에서 본 한 판은 분당 요청 100·입력 10만·출력 1만 토큰, 직접 읽은 `rate-limits` 페이지는 분당 요청 1,000·입력 100만·출력 10만 토큰. 동시 요청 제한·`x-ratelimit-*` 헤더는 언급 없음. → JetAI는 어느 쪽에도 의존하지 않고 자체 동시 요청 상한(기본 2)을 둔다.
- **데이터 보관·학습 사용**: 개인정보처리방침·약관에 위임되어 문서에서 확인 못 함 → 학습에 쓰일 수 있다고 가정(`cloud-may-train`).
- **`/v1/models`의 `pricing`이 0으로 표시**되지만 공식 정가(위)와 맞지 않는다. 메타데이터일 뿐 "계속 무료"의 근거가 아니다.
- **프로모션 종료일**: 미공지. 그래서 JetAI는 가격·크레딧 양을 코드에 넣지 않았다.

## 비용 안전성 판단
- 공급자는 무료 사용과 유료 과금을 **API로 분리하거나 확인해 주지 않는다.** 남는 보호 수단은 **계정에 결제수단을 등록하지 않는 것**(1억 토큰이 다 소진되면 호출이 거절될 뿐 청구되지 않음)이다. 단, 이것이 사실인지 JetAI는 **읽어서 확인할 수 없다.**
- 따라서 JetAI는 [FreeQuotaGuard](../architecture/free-quota-guard.md)로 **fail-closed**: 사용자가 ① 결제수단 미등록을 직접 확인하고 ② 대시보드의 남은 무료 토큰을 직접 입력했을 때만 켜지며, 입력이 오래되면(기본 24시간) 다시 막힌다. 자세한 구조는 해당 문서.
- 이 보호는 "공급자가 보장하는 것"이 아니라 "사용자의 확인 + JetAI의 보수적 계산"이다. 그래서 **결제수단을 등록하면 이 보호의 전제가 깨진다**는 경고를 화면에 둔다.

## 연결 방법 (사용자가 직접 할 일)
1. https://platform.inceptionlabs.ai 에서 가입하고 API 키를 만든다. **Billing에 결제수단을 등록하지 않는다.**
2. JetAI 서비스 연결에서 "Mercury 3 (Inception, 무료 한도 보호)"를 고르고 키를 붙여 넣는다(키는 저장소 밖 0600 파일).
3. 설정 → "무료 한도 보호 서비스": 결제수단 미등록 확인 체크 → 대시보드의 남은 무료 토큰 입력(+ 기한을 알면) → "켜기".
4. 잔액은 하루에 한 번쯤 다시 확인해 입력한다. 확인하지 않으면 24시간 뒤 자동으로 막힌다.

## JetAI에서의 사용 범위
- **쓰는 곳**: 채팅·보드·압축·코드 리뷰(채팅 호출 경로). 자동 선택(arbiter/router)은 가드가 열려 있을 때만 무료 모델로 취급한다.
- **쓰지 않는 곳**: **코드 작업(OpenCode)**. OpenCode가 서비스를 직접 호출해서 JetAI의 가드를 거치지 않기 때문에, 가드가 걸린 서비스는 코드 작업 모델 목록에서 제외하고 직접 지정해도 거절한다.
- 키는 로그·화면·상태 파일에 남기지 않는다(테스트로 확인).
