# 모바일 원격 제어

폰에서 JetAI에 질문하고, 작업을 승인·취소하고, 상태를 보는 기능입니다. 설정 → "모바일 원격 제어"에서 켭니다(기본은 꺼짐).
구현은 **텔레그램 봇**이 첫 번째이고, 다른 메신저는 같은 구조에 어댑터만 더하면 됩니다(아래 후보).

## 사용법(텔레그램)
1. 폰의 텔레그램에서 `@BotFather` → `/newbot` 으로 봇을 만든다(이름은 아무거나).
2. JetAI 설정의 "모바일 원격 제어"에 받은 토큰을 붙여 넣고 **연결**.
3. 화면에 표시된 6자리 코드를 만든 봇에게 `/start 123456` 으로 보낸다. 처음 보낸 계정만 **주인**이 된다.
4. 이후 폰에서: 글을 그냥 보내면 자동 선택으로 답한다. 명령: `/status` `/models` `/usage` `/jobs` `/failures` `/approve 번호` `/cancel 번호` `/retry 번호` `/yes` `/new` `/help`.

## 안전 규칙
| 규칙 | 구현 |
|---|---|
| 포트를 열지 않음 | PC가 `api.telegram.org`로 **밖으로만** 긴 폴링 연결 |
| 내 계정만 | 페어링 코드(일회용, 10분, 해시 저장)를 처음 맞춘 계정 하나만 허용. 그 외 사용자·그룹 대화에는 **아무 답도 하지 않음** |
| 예전 명령 재실행 금지 | 시작할 때 쌓여 있던 메시지는 건너뛰고, 2분 넘은 메시지는 버림 |
| 실행 승인은 2단계 | `/approve`·`/retry`는 `/yes`로 한 번 더 확인(2분 안), 코드 작업은 "파일을 바꿀 수 있음" 경고 |
| 남용 방지 | 분당 20개 명령, 답변은 3,800자씩 나눔 |
| 알림 폭주 방지 | 승인·검토가 필요하거나 실패한 작업을 1분에 한 번 **묶어서** 알림(처음 켤 때 예전 작업은 알리지 않음) |
| 토큰 보관 | 저장소 밖 `~/.agent-workshop/remote-secrets.json`(600). 화면·로그·API 응답에 다시 나오지 않음. 연결 해제 시 삭제 |
| 원본은 PC | 대화·큐·사용량은 PC에 있고, 폰은 보조 창구 |

**알아둘 점**: 대화가 텔레그램 서버를 거칩니다(봇 대화는 종단간 암호화가 아님). 민감한 내용은 보내지 마세요. 클라우드 무료 모델이 답하면 그 내용은 해당 서비스로도 갑니다(앱의 기존 동의 규칙 그대로).

## 구조
`workshop/remote.py`: 명령 처리 핵심(`RemoteControl.handle`, 메신저를 모름) + `TelegramChannel`(어댑터: `poll()`/`send()`). 폴링 스레드는 JetAI를 켤 때 토큰이 있으면 자동 시작, 끌 때 같이 종료. 질문은 앱과 같은 자동 선택(`chat_api._send`)을 쓰고 "텔레그램" 대화 하나에 이어서 쌓인다(`/new`로 새로 시작). API: `GET /remote`, `POST /remote/telegram|repair|disconnect`.

## 후보 비교 (다른 방법)
| 후보 | 양방향 | 설정 난이도 | 안전·프라이버시 | 메모 |
|---|---|---|---|---|
| **텔레그램 봇** (구현됨) | ✅ | 쉬움(앱 + 토큰) | 내 계정만·포트 없음. 서버 경유(비 E2E) | 무료, 폰 앱 알림 좋음 |
| **Tailscale + 웹 화면(PWA)** | ✅ 화면 전체 | 보통(양쪽 설치) | WireGuard 암호화, 사설망. `tailscale serve`로 JetAI는 127.0.0.1 그대로. **JetAI에 PIN 로그인을 먼저 추가해야 안전**(지금은 접속하면 전권) | 폰에서 지금 화면 그대로 쓰는 가장 완전한 방법. 다음 후보 1순위 |
| **ntfy** | 알림 위주(앱에서 보내기도 가능) | 쉬움(앱, 계정 불필요) | 주제 이름이 비밀(길고 무작위) + 토큰. 자체 호스팅 가능 | 완료·실패 알림만 필요하면 가장 단순 |
| Discord 봇 | ✅ | 보통(서버·권한·메시지 인텐트) | 서버 경유. 아웃바운드 웹소켓 | 이미 디스코드를 쓴다면 |
| Slack 앱 | ✅ | 어려움(앱·워크스페이스) | Socket Mode로 아웃바운드 | 회사·팀 용도 |
| Matrix(Element) | ✅ | 어려움(홈서버 계정) | 자체 호스팅·E2E 가능(봇 E2E는 복잡) | 프라이버시를 가장 중시할 때 |
| Pushover / Pushbullet | 알림만 | 쉬움 | 서버 경유 | 일방향 푸시, Pushover는 유료(일회성) |
| LINE Messaging API | ✅ | 어려움 | 웹훅(공개 주소 필요) → 포트를 열거나 터널 필요 | 이 프로젝트의 "포트 안 연다" 원칙과 충돌 |
| 카카오톡 | 제한적 | 매우 어려움 | 사업자 채널·공개 스킬 서버 필요 | 일반 개인 봇이 어려워 비추천 |
| Signal(signal-cli) | ✅ | 어려움 | E2E, 비공식 도구 | 유지보수 부담 |
| 이메일 | 느림 | 보통 | 보안 취약·지연 | 비추천 |

**제안 순서**: ① 텔레그램(지금) → ② ntfy 알림(간단) → ③ Tailscale 웹 접속 + PIN 로그인(폰에서 전체 화면).
